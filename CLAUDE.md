This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

DipDup is a Python framework for selective blockchain indexers (Tezos, EVM, Starknet, Substrate). For what it is and how it works, read [`README.md`](README.md) and [core concepts](docs/1.getting-started/2.core-concepts.md). **Key concept**: an indexer = a YAML [config](docs/1.getting-started/3.config.md) (what to index) + a Python package (handlers, hooks, models — the business logic).

## Development Commands

Run `make help` for all targets (defined in [`Makefile`](Makefile)); common ones: `make install`, `make all` (= format + lint + test), `make demos`, `make docs`, `make before_release`. Prefix everything with `uv run` (e.g. `uv run make all`, `uv run pytest tests/test_config -k <name>`) — this is not in the Makefile.

## Generated files & automation — do NOT hand-edit

Several tracked files are generated by scripts. Edit the source, then run the generator; never edit the output directly.

| Generated output | Source of truth | Regenerate with |
|---|---|---|
| `src/demo_*/` projects (incl. `dipdup.yaml`, handlers, `types/`) | `src/dipdup/projects/*/` templates (`*.j2` + `replay.yaml`) | `make demos` (`scripts/demos.py render` + `init`) |
| `schemas/dipdup-3.0.json` config JSON schema | `DipDupConfig` dataclasses | `uv run python scripts/docs.py dump-jsonschema` |
| `requirements.txt` | `pyproject.toml` / `uv.lock` | `make update` |
| Parts of `docs/` (API refs, demos table, ref tables, merged changelog) | docstrings, `replay.yaml`, `CHANGELOG.md` | `make docs` (`scripts/docs.py dump-*`) |

Docs (`docs/`) are built entirely by `scripts/docs.py` — read its source, it answers most questions. One non-obvious footgun documented nowhere else: `{{ #include ../path:from:to }}` line ranges are literal with an **exclusive end** (`:3:9` → source lines 3–8), so editing a demo/source file silently shifts every include that targets it. Re-check them and run `uv run python scripts/docs.py check-links --source docs`.

## Architecture

Concepts are documented — don't restate them here:
- Index types: [`docs/2.indexes/`](docs/2.indexes/) (per type) / [overview](docs/1.getting-started/8.indexes.md). Available: EVM (`evm_events`, `evm_transactions`), Starknet (`starknet_events`), Substrate (`substrate_events`), Tezos (`tezos_operations`, `tezos_big_maps`, `tezos_events`, `tezos_head`, `tezos_token_transfers`, `tezos_token_balances`).
- Datasources: [`docs/3.datasources/`](docs/3.datasources/) / [overview](docs/1.getting-started/7.datasources.md).
- User project layout (`dipdup.yaml`, `models/`, `handlers/`, `hooks/`, `sql/`, `deploy/`, …): [package doc](docs/1.getting-started/4.package.md).

Source-code map (NOT in user docs — this is the value-add of this file):
- Runtime pipeline: `cli.py` (entrypoint) → `config/` (Pydantic-dataclass config, root `DipDupConfig` in `config/__init__.py`) → `dipdup.py` (orchestrator) → `context.py` (`DipDupContext`, passed to handlers/hooks) → `indexes/` (per-chain `Index` impls) → `datasources/` (API clients; base `Datasource` in `datasources/__init__.py`).
- **Each index type** lives in `src/dipdup/indexes/{type}/` as `index.py` (index class) + `fetcher.py` (data fetching) + `matcher.py` (event/operation matching).

## Code Conventions

Tooling and codestyle (`ruff`, `mypy`, quotes/line length, naming) are covered by the imported contributing guide and `pyproject.toml`. Project-specific facts worth stating:

- Config classes use Pydantic dataclasses (not `BaseModel`).
- Database models use Tortoise ORM.
- Python 3.12 only.

## Testing

Tests use pytest with pytest-asyncio. Key test files:
- `tests/test_demos.py` - Integration tests running demo projects
- `tests/test_config/` - Config parsing tests
- `tests/test_datasources/` - Datasource client tests
