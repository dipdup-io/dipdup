# SQD Network

{{ #include 3.datasources/_evm_banner.md }}

{{ #include 3.datasources/_subsquid_banner.md }}

DipDup uses [SQD Network](https://docs.subsquid.io/subsquid-network/reference/evm-api/) as a source of historical data for EVM-compatible blockchains. Two gateways are available — `evm.subsquid` and `evm.sqd_portal`. They speak the same query language and return the same per-block data; they differ only in transport and authentication. DipDup uses either when possible and falls back to EVM nodes for the latest data and realtime updates.

`v2.archive.subsquid.io` gateways [require an API key](https://docs.sqd.dev/v2-keys) since 2026-05-19. Provide it via the `api_key` field; SQD Cloud users are unaffected. v2.archive is scheduled for sunset in 2026, so new projects should prefer the Portal gateway below.

## SQD Portal gateway

[SQD Portal](https://portal.sqd.dev) is the successor to v2.archive: a single streaming endpoint (NDJSON) instead of worker indirection, currently keyless for public datasets. Use the `evm.sqd_portal` kind with the per-dataset Portal URL:

```yaml [dipdup.yaml]
datasources:
  sqd_portal:
    kind: evm.sqd_portal
    url: https://portal.sqd.dev/datasets/ethereum-mainnet
    # api_key: ${SQD_PORTAL_API_KEY:-}  # optional
```

The two kinds are interchangeable in index definitions, so you can switch a project from one gateway to the other by changing only the datasource block.
