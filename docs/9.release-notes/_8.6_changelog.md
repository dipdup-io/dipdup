## Changes since 8.5

### Added

- context: Added `get_evm_portal_datasource` method to access `evm.sqd_portal` datasources from handlers and hooks with a precise type.
- context: `ctx.execute_sql_script(..., dedicated_connection=True)` runs the scripts on a separate PostgreSQL connection, so a long statement like `REFRESH MATERIALIZED VIEW` in a job no longer pauses indexing.
- database: Postgres session settings like `synchronous_commit` or `work_mem` can be set in `database.server_settings` and apply to every DipDup connection, including indexing transactions that a `SET` from a hook never reaches; values can be strings, numbers or booleans (`on`/`off`); `search_path` (use `schema_name` instead) and `client_encoding` are rejected in any letter case.
- evm.sqd_portal: Added a new datasource backed by the SQD Portal (`portal.sqd.dev`), a streaming alternative to the v2.archive `evm.subsquid` gateway.
- evm.subsquid, starknet.subsquid, substrate.subsquid: Added `api_key` option to authenticate with `v2.archive.subsquid.io` gateways, which require a key since 2026-05-19.
- project: `dipdup new` can add GitHub Actions workflows (lint, config check, Docker image build) and a VS Code debugger config; existing projects get them by setting `ci: github` or `ide: vscode` in `configs/replay.yaml` and running `dipdup init`.
- watchdog: The first warning about a stuck callback or transaction includes the chain of coroutines the task is waiting on.
- watchdog: `ctx.watchdog.heartbeat` and `ctx.watchdog.reset` accept an optional `name` to keep a separate countdown for each name.

### Fixed

- cli: A crash report that cannot be written (read-only or full disk) no longer replaces the actual error; DipDup logs a warning and skips the report.
- cli: A crashed `dipdup run` no longer logs a spurious `RuntimeError: aclose()` next to the actual error, which reached Sentry as a separate issue.
- cli: `dipdup new` creates the `<package> -> .` symlink in the new project, so `mypy` resolves package imports and handlers are formatted the same as by a later `make format lint` in the project root.
- cli: `dipdup self install` no longer ignores `--path`, `--ref` and `--pre` when DipDup is already installed.
- cli: `dipdup self update` explains how to update installations not managed by `uv tool`.
- coinbase: The datasource calls `api.exchange.coinbase.com`, so `get_candles` works again; the retired `api.pro.coinbase.com` answered every request with 503.
- coinbase: `get_candles` no longer returns the same candle twice when the range spans more than 300 candles.
- coinbase: `get_oracle_prices` raises `UnsupportedFeatureError` without making a request, since Coinbase has deprecated its Price Oracle API.
- config: `buffer_size` no longer conflicts with the `advanced.rollback_depth` value that validation derives itself, which made the option unusable.
- config: `first_level` and `last_level` set both in a template and where it is used (an `indexes` entry or `ctx.add_index`) no longer produce a level that is neither of the two (500 and 1001 gave 1021, skipping blocks); the value set where the template is used wins.
- config: `tezos.head` and `tezos.operations_unfiltered` indexes created from a template (in `indexes` or with `ctx.add_index`) no longer fail with `handlers: Unexpected keyword argument`.
- context: A database connection lost in the middle of a rollback no longer leaves the reverted data under the old index level, which made the index skip the new branch after a restart.
- context: An index is no longer rewound when the rollback was skipped because reindexing is ignored.
- context: `ctx.rollback` reverts all changes made above the target level.
- datasources: A realtime connection closed by the server with an error (e.g. TzKT's `ClientTimeoutInterval`) is reconnected instead of crashing the indexer with `FrozenInstanceError`.
- evm.events: Fixed parsing nested event payloads with fields named after Python keywords.
- evm.node: A project with both `evm.events` and `evm.transactions` indexes on one node datasource opens two `newHeads` subscriptions and gets every head announced twice; the second announcement no longer crashes the datasource with a `KeyError` nor fires a phantom rollback.
- evm.node: Omit unset `address`/`topics` from `logs` subscriptions instead of sending `null`, which strict JSON-RPC nodes (Octez/Etherlink EVM) reject.
- hasura: Views created without reindexing (e.g. by an `on_restart` SQL script) appear in the GraphQL API after the next start instead of only after `hasura configure --force`.
- http: Requests rejected with a 4xx status (except 408 and 429) are no longer retried, so errors like 404 or 400 reach the caller immediately instead of after the full retry backoff.
- http: Treat HTTP 503 responses as rate limiting, applying `ratelimit_sleep` backoff like 429; many gateways shed load with 503 instead of 429.
- http: `Retry-After` on 429 and 503 responses is honored both as seconds and as an HTTP date; when it is longer than two minutes (or `ratelimit_sleep`, if larger), the request fails right away instead of waiting that long between every retry.
- index: A chain reorg received while the index is falling behind the datasource is no longer dropped when the index resyncs, which left the data of the orphaned blocks in the database.
- index: An index that reached its `last_level` no longer keeps the other indexes from switching to realtime and no longer collects realtime messages.
- index: Rollbacks are no longer skipped when realtime messages are still queued.
- ipfs: The default `url` is now `https://ipfs.filebase.io/ipfs`, since `ipfs.io` no longer serves requests; it is a public gateway for testing and light usage, so set your own `url` for production.
- metrics: Progress is no longer stuck at `estimating...` for indexes that skip history or when an index is added while others are syncing, and no longer goes negative after a rollback.
- models: `bulk_create` called with a generator inserts the objects instead of nothing.
- project: A project created with `dipdup new` from the `demo_tezos_etherlink` template uses the chosen package name in `dipdup.yaml`.
- report: Fixed `KeyError: 'stacktrace'` when saving a crashdump for a chained exception whose `__context__`/`__cause__` cause has no traceback.
- sentry: Fixed crash on init with sentry-sdk 2.61+, where `DEFAULT_MAX_VALUE_LENGTH` became `None`.
- sentry: Set process-wide `dipdup.*` tags on the global scope so they appear on all error reports.
- subscriptions: The datasource sync level is kept on disconnect, so the indexer no longer crashes with `Neither current nor sync level is known` and metrics no longer freeze while reconnecting.
- tezos.operations: Handlers get `None` for every missing `optional` pattern item, including trailing ones, instead of failing with `TypeError`; a handler whose required item is missing at the end of a group is no longer called; a pattern of only optional items is no longer called when none of them matched and no longer hangs the indexer.
- tezos.operations: Handlers with a pattern item without `entrypoint` are called for any entrypoint of the contract, not only `default`; a `tezos.operations_unfiltered` index next to a filtered one gets every transaction in realtime, not only those with the neighbours' entrypoints. Affected projects start getting handler calls that were silently skipped before; levels already indexed are not revisited, so reindex to get the missed ones.
- tezos.operations: Transactions unrelated to any indexed address or code hash are skipped before matching also when only addresses or only code hashes are set; a transaction pattern without `source` and `destination` gets every transaction with any combination of filters.
- tezos.token_balances: Handlers with `token_id` get balances during sync; the filter was sent to TzKT as its internal token ID, so the request matched nothing. The whole snapshot is fetched again on the next start, so the missed balances arrive without a reindex.
- tezos.token_balances: Handlers with different filters in one index no longer miss balances during sync: a `contract` or `token_id` filter is sent to TzKT only when every handler of the index sets it, since TzKT requires both to match at once. The whole snapshot is fetched again on the next start, so the missed balances arrive without a reindex.
- tezos.token_transfers: Handlers with `token_id` get transfers during sync; the filter was sent to TzKT as its internal token ID, so the request matched nothing. Levels already indexed are not revisited, so reindex to get the missed transfers.
- tezos.token_transfers: Handlers with different filters in one index no longer miss transfers during sync: a `contract`, `token_id`, `from` or `to` filter is sent to TzKT only when every handler of the index sets it, since TzKT requires all of them to match at once. Levels already indexed are not revisited, so reindex to get the missed transfers.
- tezos.tzkt: A TzKT outage after realtime has started no longer crashes the indexer with `RuntimeError: The socket was never run`.
- tezos.tzkt: A realtime connection is reconnected after a failed negotiation instead of crashing the indexer: a refused connection crashed it at once, an expired connection id after about ten drops.
- tezos.tzkt: A subscription request lost with a dropped realtime connection is sent again after reconnecting instead of blocking the indexer forever.
- tezos.tzkt: All buffered messages of a rolled-back level are dropped; one message per level could survive the reorg and be processed later.
- transactions: A rollback that fails after the database connection is lost no longer replaces the error that caused it; the rollback error is attached to it as a note.
- transactions: Every index keeps model updates for its own `rollback_depth` levels instead of the most advanced index deciding for all of them.
- watchdog: A long-running callback is no longer hidden by other callbacks starting or finishing.
- watchdog: A transaction stuck in one index is no longer hidden by other indexes finishing theirs, so `action: exception` fires as configured.
- watchdog: Callback warnings name the stuck handler with its index, or the stuck hook; transaction warnings name the index and level when the transaction belongs to an index.
- watchdog: Hooks running as daemon jobs are no longer reported by the `callback` trigger, and `ctx.watchdog.heartbeat(WatchdogTrigger.callback)` inside them does nothing.

### Changed

- codegen: Empty-object Michelson `unit` fields no longer accept non-empty objects.
- codegen: Fields named after Python builtins are aliased (`bool` becomes `bool_`); update attribute access in handlers after regenerating types.
- codegen: Nullable required fields are no longer optional; a payload without the key fails validation.
- codegen: Root models generated from non-nullable schemas no longer accept `None`.
- datasources: Realtime connection failures are logged at `WARNING` level as `Realtime connection failed: ...` instead of `ERROR` as `Websocket connection error: ...`; alerts on the old message no longer fire.
- datasources: The realtime `http.retry_count` limit counts consecutive connection failures instead of failures over the whole lifetime of the process, and also applies to `evm.node` and to `substrate.node`, which used to reconnect forever; a connection lost before all subscriptions are confirmed counts as failed.
- demo_tezos_etherlink: Replaced decommissioned parisnet contracts with shadownet ones.
- metrics: Progress in the status line and in `dipdup_progress`, `dipdup_levels_indexed_total`, `dipdup_levels_total` covers the whole range of every index, from its `first_level` to the head, instead of the levels left at the start of the current run; after a restart at 90% of the history it continues from 90% instead of starting from zero.
- tezos.tzkt: Replaced decommissioned ghostnet with shadownet in known testnet URLs and the `demo_tezos_events` project.
- tezos.tzkt: The realtime connection uses `http.connection_timeout` (60 seconds by default) instead of a hardcoded 30 seconds.
- watchdog: A regular (non-daemon) job or hook that runs longer than the `callback` timeout is now reported, while previously any other callback starting or finishing hid it; an `atomic: true` one is also reported by the `transaction` trigger. To allow it, raise the timeout or call `ctx.watchdog.reset(WatchdogTrigger.callback)` inside it, plus `ctx.watchdog.reset(WatchdogTrigger.transaction)` for an atomic one.
- watchdog: The `websocket` trigger is now armed by default: if an open realtime connection delivers no messages for its timeout (60 seconds unless configured), DipDup warns about it; a datasource without subscriptions is not watched. Previously DipDup never armed it, so it did not fire. If you set `websocket: action: exception`, such a silence now stops the indexer.
- watchdog: `ctx.watchdog.heartbeat(trigger)` and `ctx.watchdog.reset(trigger)` without a name act on the callbacks or transactions of that trigger watched in the calling code and the tasks it spawns, not on every callback or transaction at once. Inside a watched callback or transaction with none of that kind running, a name-less heartbeat does nothing: for example, `heartbeat(WatchdogTrigger.transaction)` in a non-atomic hook or `heartbeat(WatchdogTrigger.websocket)` in any callback. Outside any watched callback or transaction, the trigger keeps a single countdown as before.

### Performance

- index: Indexes that match nothing at a realtime level no longer save their level one by one; the levels of all such indexes are saved in a single statement after every dispatcher loop.

### Security

- deps: Updated `aiohttp` to 3.14.5 and `msgpack` to 1.2.4 to fix published advisories, including unbounded memory use in both ([GHSA-2g87-pp6c-29x5](https://github.com/advisories/GHSA-2g87-pp6c-29x5), [GHSA-j586-36cw-2gc2](https://github.com/advisories/GHSA-j586-36cw-2gc2)).
- deps: Updated `datamodel-code-generator` to 0.71.0 to fix code injection via crafted JSON schemas ([GHSA-5578-w22f-pfx9](https://github.com/advisories/GHSA-5578-w22f-pfx9)).
